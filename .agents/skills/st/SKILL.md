# 仕様・テストケース

1. 確定した要件から入力、出力、副作用、状態遷移を定義する。条件の組み合わせが多い場合は決定表を使う。
2. 各ケースに要件ID、前提、操作、観測可能な期待結果を持たせる。正常系に加え、適用される境界、異常系、既存機能への回帰を含める。
3. 期待結果は要件・合意事項から導出する。独立した確認が可能なら `tc-judge` に要件とケースを渡し、実装差分は判断材料から外す。
4. 未確定事項と要件の対応漏れを記載し、指定の保存先へ出す。保存先の指定がなければ会話に提示する。検証が失敗した際に期待値を変える場合は、要件上の根拠を記録する。
