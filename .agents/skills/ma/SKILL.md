# make-anki

## 呼び出し方

- `$ma` — 引数と直前の文脈からモードを自動判別する
- `$ma ref <節番号・ファイル・範囲>` — **refモード**：参考書MD・講義・節からの一括抽出
- `$ma term <用語1> <用語2> …` — **termモード**：演習・会話中に出てきた用語の即席カード化

### 自動判別ルール（引数なし・モード指定なしの場合）

- 節番号・章・参考書ファイル・「疑問リスト」が与えられている → **ref**
- 個別用語の列挙、または直前の会話（過去問演習・解説）に登場した語の指定 → **term**
- どちらとも取れる場合は、実行前に1回だけ確認質問する

## 共通出力ルール

### CSV(1)：概念理解用

形式：`"意味","単語"`

- **単語欄（第2フィールド）は用語・名詞（句）・値のみ。動詞で終わる文や理由節
  （〜する／〜できる／〜のため／〜だから／〜こと）を入れないこと**。
  意味欄と同じような説明文を単語欄に書いてしまう誤りが起きやすいので、
  出力前に単語欄だけを見て「これは名詞か？」を必ず確認する
  - 説明文の続きが単語欄に入ってしまいがちなケース：「〜する理由」「〜した場合に起きること」
    「〜できない制約」を問う意味欄を作ると、単語欄に文が入り込みやすい。
    その場合は**問いを反転して名詞的な答えに絞る**か、**複数の条件に分割する**
    - 例）OK（分割）: 3行に分けてそれぞれ単語欄を1つの攻撃名にする
- 「〜とは」系 → `"意味の説明","単語"` で1行
- 「AとBの違い」系 → 比較対象ごとに**1行ずつ**分割して出力
  - `（〇〇との違い）` のような付記・注釈は付けないこと。代わりに、**説明文単独で答えが
    一意に定まる**ように、対比点が伝わる表現を選ぶこと
  - 例）リンゴとみかんの違い
    - `"赤くて甘い果実","リンゴ"`
    - `"橙色で酸味のある果実","みかん"`
- 似た概念が複数ある場合も同様に、説明文だけでどの単語か絞れる書き方にすること
- 単語が英字の略語・頭字語の場合、**例外なく単語欄に正式名称（英語表記）を括弧で併記**すること。
  組織名（JVN等）だけでなく、**暗号・規格・アルゴリズム名（RSA・DSA・ECDSA・AES・DH・ECDH・
  KDC・SHA・MD5・HMAC・AEAD・PQC・CBC・CTR・ECB・GCM等）も一律対象**。
  「有名だから」「試験でよく出るから」といった理由で省略しないこと
  - 例）`"素因数分解の困難性を利用…","RSA（Rivest-Shamir-Adleman）"`
  - 対象外：Camellia・KCipher-2・ChaCha20など、略語ではなく固有の製品/アルゴリズム名そのもの
  - 略語の由来が説明の記憶フックになる場合は、意味欄にキーワードを織り込んでよい（例：「共有」「レスキュー」）
  - **出力前に単語欄を見直し、正式名称の括弧がない英字略語が1つでも残っていないか必ずセルフチェックすること**
- 列挙系（3要件・3原則・構成要素など） → **要素ごとに分解**して意味→単語形式にする。
  問い→答え形式の行（例：`"〜の3要件は？","A・B・C"`）は作らないこと
  - 例）営業秘密の3要件
    - `"営業秘密の要件の一つ。秘密として管理されていること","秘密管理性"`
    - `"営業秘密の要件の一つ。事業活動に有用であること","有用性"`
    - `"営業秘密の要件の一つ。公然と知られていないこと","非公知性"`
- 同じ単語が複数回登場する場合、単語欄が同一の行は**1行に統合**すること
  - 統合する際は最も情報量が多い説明を採用し、他の説明は補足として括弧内に加えること

### CSV(2)：コマンドリファレンス用

形式：`"操作の説明","コマンド"`

- 説明は体言止めまたは動詞止め（短く簡潔に）。疑問文にしないこと
- コマンドには主要オプション・引数も含める
- コマンドリファレンスの表に記載されたもの**すべて**を出力すること
- 加えて、教材内の「試験対策ポイント」「注意」に記載されたコマンド・オプションも漏れなく含めること
- 例）
  - `"システムを即時停止","shutdown now"`
  - `"システムを停止（電源は切らない）","shutdown -H now"`
  - `"システムを停止して電源も切る","shutdown -P now"`

### 出力形式

- CSV(1)とCSV(2)を区切りなく**1つのCSVファイル**として出力（CSV(1)が先）
- ダブルクォート囲み・カンマ区切り・**ヘッダ行なし**・UTF-8
- 説明文は暗記に適した短さにすること（目安：30文字以内）
- **必ずファイル出力すること**（チャットへの貼り付けは不要）
- 事実性の担保：意味の説明は手元の教材・公式資料で確認できる内容のみとし、記憶や推測で書かないこと

## 出力先・命名

出力先はカレントプロジェクトの `anki/` ディレクトリ（なければ作成する）。

| モード | ファイル名 |
|---|---|
| ref | `anki/<節番号>_<節名>.csv`（例：`anki/1.2_ISMS.csv`） |
| term | 呼び出しごとに**新ファイル**。学習中のセクションに紐づけて `anki/<節番号>_用語.csv`。同名が既にあれば `_2`, `_3` と連番を付ける |

## モード別の入力

### refモード

- 対象：指定された参考書MD・講義テキスト・節（プロジェクトのルールに教材の読み方があればそれに従う）
- ユーザーから「疑問リスト」が与えられた場合はそれを CSV(1) の対象とし、
  与えられなければ対象範囲の重要用語を網羅的にカード化する
- 「コマンドリファレンス対象セクション」が指定された場合のみ CSV(2) を生成する

### termモード

- 各用語をCSV(1)のルールでカード化する。
- 生成後、何をカード化したか（件数と単語一覧）を1〜2行で報告する
