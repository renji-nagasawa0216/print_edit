# Playwright 検証

1. 対象の受入条件、ベースURL、既存の Playwright 設定と実行手順を確認する。使い捨てのテスト環境とフィクスチャを使用する。
2. ケース設計時は要件と決定事項から期待値を定める。実行時は公開された画面・API の振る舞いを比較する。既存の安定した locator とフィクスチャを再利用する。
3. 最初に対象ケースを絞って実行する。失敗時は、該当ケースのエラー、必要なトレースや画面、ログの関連部分を読む。環境・テストの前提・実装のどこで失敗したかを特定する。
4. 共通設定・認証フィクスチャ・依存ロックファイルの変更が必要なら対象範囲を確認する。テストに認証情報を直書きしない。期待値の変更は要件上の根拠を付ける。
5. ケースID、実行コマンド、結果、失敗の根拠、未実行範囲を報告する。
