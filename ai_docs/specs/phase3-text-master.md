# 段階③　テキスト入り名刺マスタ

## 要件と受入条件

根拠は `#1_req.tsv` の R10〜R10-5 と `ai_docs/documents/main/card_master_request.md` の j13〜j16。

| 要件 | 操作と確認結果 |
|---|---|
| R10・R10-4 | 元の名刺マスタからテキスト入りの子を作り、保存後も子の文字を再編集できる。親の切り出し画像はそのまま使える。 |
| R10-1 | Macのフォントとデータフォルダ内の fonts に追加した TTF・OTF・TTC を選べる。PDFには文字の輪郭をベクターで描く。 |
| R10-2 | 一枚に複数のテキストボックスを置き、それぞれの内容、位置、幅、文字サイズ、左・中央・右揃えを保存して開き直せる。回転と縦書きは将来対応。 |
| R10-3・R10-5 | 黒からグレーまでの濃淡と太さを指定できる。太字書体がない場合は輪郭を太らせる。カラー選択は無効表示。 |

## 親子の扱い

子がある親を削除しようとしたら操作を止め、対象の子を表示する。子をすべてマスタ一覧から外した後は親も削除できる。作成済みのPDFは履歴に残る。

## 画面と検証ケース

名刺マスタに作成・編集の入口を置く。子の編集では名刺画像と文字の配置を見ながら、選択したボックスの内容と書式を変える。狭い画面ではプレビューと操作欄を縦に並べる。

| ケース | 操作 | 期待結果 |
|---|---|---|
| T1 親と子 | 親から2種類の子を保存して再読み込み | 親の画像は同一。各子の文字と名前を個別に復元 |
| T2 編集 | ボックスを追加、移動し、幅、文字サイズ、揃え、太さ、濃淡を変更 | プレビューと保存後の編集画面で設定が一致 |
| T3 PDF | 同じ親を持つ異なる子を別スロットに配置 | 指定したスロットに各子の文字輪郭があり、後で子を編集しても保存済みPDFは同一 |
| T4 削除 | 子がある親を削除し、子を削除した後に再試行 | 初回は対象の子を表示して中止。子がなくなれば成功 |
| T5 入力エラー | 不明なフォントや不正な寸法で保存 | エラーを表示し、直前に保存した内容を保持 |

## 検証記録

- APIテストで、元画像の保持、複数の子の保存・再編集、削除制御、異常入力での保存拒否、シート内の子ごとのベクター輪郭、作成済みPDFの保持を確認した。追加フォントはTTF・CFF OpenType・複数書体のTTCで確認した。
- 複数PDFの作成前に使用フォントを検証する。登録後にフォントが外された場合は、作成・送信の開始前に422を返す。
- pytestの全体実行では成功603件・失敗226件・スキップ26件。失敗のテストIDは引き継ぎ7と一致した。最終のAPI・段階③の再実行は15件成功。macOS実機のフォント列挙とプリンタでの出力は未検証。
- Playwrightはセットアップを含む101件成功。段階③ではドラッグによる移動、再読み込み後の再編集、子がある親の削除防止、PDFの取得、幅390pxでの作成をブラウザで確認した。
